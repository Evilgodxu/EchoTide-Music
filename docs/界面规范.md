# 界面规范

本文件固定忆潮音乐的界面语言，供后来者与 AI 在新增、修改界面对照。它描述的是**已经成立的风格**，
不是待实现的目标：文档与代码不一致时以本文件为准，由改动方把代码补齐。

效力与维护：

- `AGENTS.md` 的「界面风格」一节是本文件的摘要；两者冲突以本文件为准。
- 新增颜色角色、圆角档位、字号档、动效时长，先在本文件登记，再落代码。
- 不接受「代码先偏移、文档后追认」。评审时以本文件为判据。

## 1. 风格立场

1. **内容优先，低装饰。** 层次由色阶与留白建立，不靠阴影、描边堆叠、装饰性渐变。
   界面层不使用 `HorizontalDivider`，也不使用 `Modifier.shadow`。
2. **深浅同等。** 每个界面在浅色与深色下都必须成立；深色不是浅色的补丁。
3. **一个沉浸舞台。** 首页（含在线搜索、歌单页）是唯一铺封面衍生背景、隐藏系统栏的页面；
   其余页面是跟随主题的「纸面」。

由此得出的禁令：

- 不在普通页面使用封面取色、位图背景或模糊层。
- 不为「好看」添加动效或强调色。
- 不新增装饰性渐变；渐变只用于沉浸背景与可读性遮罩。

## 2. 色彩

### 2.1 唯一来源

业务代码取色一律 `MaterialTheme.colorScheme.*`。白名单之外出现颜色字面量即视为偏移。

允许的例外只有三类：

| 位置 | 内容 | 理由 |
|---|---|---|
| `theme/Color.kt` | 色板定义 | 唯一的 RGB 字面量来源 |
| `LibraryAnalysisSheet` 的分类色 | 图表 6 色 | 数据可视化需要色相区分，语义色角色不够用 |
| 沉浸层前景（首页、播放面板、歌单拖拽行） | 固定白 / 半透明白 | 底色是封面衍生色，不随主题变化 |

新增例外须在提交说明里写清「为什么语义色不够」，并在上表登记。

### 2.2 色板基线

色板取自 GitHub Primer 的明暗两套语义色，主色为靛蓝。下表是高频角色，完整定义见 `theme/Color.kt`：

| 角色 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `background` | `#F6F8FA` | `#0D1117` | 页面底 |
| `surface` | `#FFFFFF` | `#161B22` | 卡片、对话框、浮层 |
| `surfaceContainerHigh` | `#E8ECF0` | `#252B33` | 浮层内的可点容器、菜单容器 |
| `onSurface` | `#1F2328` | `#F0F6FC` | 主文案、主图标 |
| `onSurfaceVariant` | `#656D76` | `#8B949E` | 弱化文案、分区标题 |
| `outline` | `#D0D7DE` | `#30363D` | 输入框描边 |
| `primary` | `#3F51B5` | `#B1B8DF` | 当前项、激活态 |
| `error` | `#CF222E` | `#F85149` | 破坏性操作、失败 |
| 成功态（`LocalSuccessColor`） | `#3FB950` | `#56D364` | 完成类正反馈 |

### 2.3 层级

页面底 → `background`；卡片、对话框、浮层 → `surface`；浮层内的可点容器 → `surfaceContainerHigh`；
输入框与次要按钮底 → `onSurface.copy(alpha = 0.08f)`。

- 需要拉开层次时**跳一档**，不新造中间色：不要在 `surface` 与 `surfaceContainerHigh` 之间随手取
  `surfaceContainer`。
- 卡片内不再套卡片。第二层用底色或留白区分。
- 浮层卡片允许 `surface.copy(alpha = 0.96f)`（`AppAlpha.FloatingSurface`），让底下内容透出一点。

### 2.4 前景与强调

| 用途 | 取值 |
|---|---|
| 主文案、主图标 | `onSurface` |
| 次要文案（副标题、说明） | `onSurface.copy(alpha = AppAlpha.Secondary)` |
| 弱化 / 占位 | `onSurfaceVariant` |
| 禁用 | `onSurface.copy(alpha = AppAlpha.Disabled)` |
| 当前项 / 激活 | `primary`；选中底 `primary.copy(alpha = AppAlpha.Selected)` |
| 破坏性 | `error` |
| 完成类正反馈 | `LocalSuccessColor.current` |

- `tertiary` 在色板中预留但未使用；不要为「多一个强调色」启用它。
- `primary` 只标记状态，不做装饰：不给卡片描边，不给标题上色。
- 错误提示底可用 `error.copy(alpha = 0.08f)`（见 `MusicErrorBanner`）。

### 2.5 沉浸层

首页背景由封面取色生成，前景固定白色系：主文 `Color.White`，次要 `Color.White.copy(alpha = 0.6f)`。
这一层允许固定色，因为底色不随主题走；放在这一层的组件不需要、也不应该读 `colorScheme` 的前景角色。
新组件若要同时服务沉浸层与普通页面，把前景色作为参数传入，不要在组件内部判断主题。
沉浸层内的白色填充可用 0.12（如搜索历史标签底），这个档位不引入普通页面。

## 3. 形状

| 档位 | 令牌 | 用途 |
|---|---|---|
| 20dp | `AppShape.Container` | 卡片（`GroupCard`）、对话框（`DialogCard`） |
| 12dp | `AppShape.Option` | 浮层内的可点选项行（`DialogOption`） |
| 10dp | `AppShape.Control` | 页面内联的输入框、标签、紧凑按钮、内联块 |
| 8dp | `AppShape.Media` | 封面、缩略图、媒体块 |
| 6dp | `AppShape.Micro` | 极小标记（迷你播放器小封面、播放模式小块） |
| 2dp / 1dp | 就地取值 | 进度条、细高亮条 |

- 同一层级的容器只用同一档：卡片不出现 16dp 或 24dp 的圆角。
- 全圆角（`CircleShape`）只用于圆形图标按钮与圆形封面位。
- 圆角不随窗口尺寸变化。

## 4. 间距与尺寸

- 基准 4dp；允许 4 / 6 / 8 / 10 / 12 / 14 / 16 / 20 / 24。其中 6 / 10 / 14 只用于行内视觉微调，
  不用于页面级布局。
- 页面水平内边距 16dp（`AppSpacing.PageHorizontal`）；宽窗把行宽收窄到 720dp
  （`WindowSizeClass.contentMaxWidth`），窄窗满宽。
- 分区标题：上 20dp、下 10dp（`AppSpacing.SectionTop` / `SectionBottom`）。
- 卡片内列表行：左右 16dp、上下 12dp（`AppSpacing.RowHorizontal` / `RowVertical`）。
- 对话框：内边距 16dp（`AppSpacing.Dialog`）；选项行左右 8dp、上下 4dp，有图标时内部左右再留 12dp，
  纵向常规 14dp、紧凑 4dp。
- 图标：默认 24dp；行内次要 20dp；极小 16dp。
- 可点区域以 48dp 为准（Material 图标按钮的默认触控尺寸）。紧凑档 32dp 只用于两处：面板/对话框标题栏的
  返回与关闭、行内次要操作（如歌单行收藏，30dp）。用紧凑档要在同一文件注释说明「为什么不能占满 48dp」，
  不要把它当默认尺寸。

## 5. 排版

字体用系统默认（`FontFamily.Default`），不嵌字体。`Typography` 只覆盖 `bodyLarge`
（16sp / 24sp / 0.5sp），其余角色沿用 M3 默认。

| 字号 | 用途 |
|---|---|
| 28sp | 计时器等超大数字 |
| 20sp | 沉浸页分组标题 |
| 18sp | 页面主标题、统计数字 |
| 16sp | 页面主行、设置项标题、对话框标题 |
| 15sp | 次级标题、面板标题 |
| 14sp | 副标题、说明行 |
| 13sp | 密集列表正文（歌单行、信息行） |
| 12sp | 辅助信息（计数、时长、状态） |
| 11sp | 标签、角标 |
| 10sp | 极小标记（音质角标、单位） |

- 字重：`Normal` 正文 / `Medium` 次强调 / `SemiBold` 强调。新代码不使用 `Bold`（现有 4 处为历史遗留）。
- 分区标题固定为：`labelSmall` + `SemiBold` + `letterSpacing 1.2sp` + `onSurfaceVariant`（见 `GroupCard`）。
- 同屏同层级文案必须同字号；不允许「这里 12、那里 13」表达同一语义。
- 表外字号是历史个例（如 `SearchHistoryTags` 的 12.5sp、迷你播放器的 9sp），新代码不得再取表外值。

## 6. 组件选用

| 需求 | 组件 | 位置 |
|---|---|---|
| 二级页骨架 | `Scaffold` + `PageTopBar` + `ContentPane` | `ui/component/` |
| 分组卡片 | `GroupCard` | `ui/component/section/` |
| 对话框 | `AppDialog`（首选）/ `DialogCard`（完全自定义内容） | `ui/component/` |
| 对话框选项行 | `DialogOption` | `ui/component/AppDialog.kt` |
| 开关 | `AppSwitch` | `ui/component/` |
| 可展开选择 | `ExpandPicker` | `ui/component/` |
| 页面标题栏 | `PageTopBar` | `ui/component/` |
| 图标 | `AppIcons` | `ui/icons/` |

- 上表已覆盖的能力不得自建等价物；确需新形态时，先给共享组件加可选参数（默认值保持现有外观），
  不要复制一份私有实现。
- 图标只从 `AppIcons` 取（本地 Material Symbols Outlined 子集），不引入 `material-icons-extended`，
  不混用其他图标库。
- 跨页面复用上提到 `ui/component/`，单页专用下沉到该页 `component/`（见 `AGENTS.md` 组件归属）。

参考实现：设置页的完整链路（`SettingsAssembly` → `SettingsPane` → `GroupCard` + `SettingsEntry`）
是「纸面」形态的样板；`AppDialog` + `DialogOption` 是浮层形态的样板。

## 7. 动效

| 场景 | 时长 | 令牌 |
|---|---|---|
| 按压、勾选等即时反馈 | 120ms | `AppMotion.Micro` |
| 小元素淡入淡出 | 150ms | `AppMotion.Small` |
| 中等区块出现 / 让位 | 200ms | `AppMotion.Medium` |
| 页面内标准转场 | 350ms | `AppMotion.Standard` |

- 缓动：默认 `tween`；连续位移（歌词滚动、跑马灯）用 `LinearEasing`；手势跟手与拖拽排序用 `spring`。
- 只表达状态转换。不做逐元素入场动画，不做循环装饰动画。屏幕级动效只有两处：主题切换的整屏揭示
  （`ScreenRevealHost`）与切歌的封面/背景过渡。
- 动画只改 `alpha` / `offset` / `scale` / `rotation` 等绘制属性，不逐帧生成位图。
  背景流动是唯一例外，且已有 30fps 节流与「关闭背景流动」开关。

## 8. 系统栏与沉浸

- 首页（含横屏）请求 `HIDE_ALL`（`SystemBarAppearance.isHomePortraitImmersive`，变量名沿用早期的
  Portrait 叫法，实际横屏同样生效），离开首页即撤销。
- 首页状态栏固定白色图标（`HomeScreen` 的 `SideEffect` 覆盖 `LocalStatusBarLight`）；
  其余页面跟随主题（`StatusBarStyleEffect`）。
- 导航栏避让由各页自理：二级页在内容列上 `navigationBarsPadding()`，没有统一兜底。
  新增二级页漏了这一步，滚到底会被三键导航压住。
- `window.isNavigationBarContrastEnforced = false` 在 `MainActivity` 设置，页面不要重复处理。

## 9. 状态呈现

| 状态 | 呈现 | 实现 |
|---|---|---|
| 轻提示（已保存、已切换） | 系统 Toast，短时 | `Toast.makeText(...)` |
| 播放/加载失败 | 就地错误横幅：`error` 文字 11sp、`error` 8% 底、6dp 圆角，2 秒自动消失 | `MusicErrorBanner` |
| 加载中 | 内联进度圈（18 或 24dp、`strokeWidth = 2.dp`），占位与原内容同高 | `CircularProgressIndicator` |
| 空内容 | 就地一行说明，写清「为什么空」与「该做什么」；不画插画、不铺满屏 | `LibraryEmptyHint` |
| 禁用 | 前景降到 `AppAlpha.Disabled`，不把整块控件调透明 | `DialogOption` 的 `enabled` |

- 不使用 `Snackbar` / `SnackbarHost`：轻提示一律 Toast，避免与播放器底栏抢位。
- 不使用全屏 loading 遮罩；加载指示放在将被内容替换的位置。
- 「未授权 / 扫描中 / 空库」必须分成三条文案，不合并成一句「暂无内容」——三者该做的事不同。

## 10. 文案与本地化

- 用户可见文案一律进 `res/values/strings.xml` 与 `values-en/strings.xml`，不在 Compose 里写中文字面量。
- 图标 `contentDescription` 必填；纯装饰图标传 `null`。
- 同一动作在不同页面复用同一条字符串资源，不为措辞微调新增副本。

## 11. 判例

| 场景 | 做法 |
|---|---|
| 新增一个设置项 | 放进现有 `GroupCard`，用 `SettingsEntry` 的行（左右 16、上下 12 内边距、16sp 标题、14sp 副标题 60% 透明），不自建行布局 |
| 设置里再分一层 | 页内层级留在设置页内（`SettingsPage` + 与路由同观感的 300ms 位移）：只换标题与内容、接管返回键；层级可自带 ViewModel，但不新建路由。路由只留给从别的页面进入的目的地（频谱、元数据） |
| 分区标题已写明该项是什么 | `SettingsEntry` 只留当前取值，不传 `subtitle`，避免同一句话读两遍 |
| 二级页怎么返回 | 标题栏返回键与空白处右滑同一出口（`Modifier.swipeBack`）：纵向滚动、开关拖动、子级横向分页都不受影响；手势只收无人认领的横向位移 |
| 需要强调某个值 | 用 `SemiBold` 或 `primary` 文字；不加底色块、不加描边 |
| 需要分隔两组内容 | 换一个 `GroupCard` 或增大留白；不画分割线 |
| 对话框里选一项 | `AppDialog` + `DialogOption`，选中用 10% primary 底 + `SemiBold`，不加勾选图标 |
| 深色下看不清 | 换色阶（如 `surface` → `surfaceContainerHigh`），不把透明度调成 0.85 这类中间值 |
| 想加一个强调色 | 先用 `primary` / `error` / `LocalSuccessColor`；都不合适说明语义没想清，不要启用 `tertiary` |
| 想加投影 | 不加。浮层用 `tonalElevation = 4.dp` 或色阶区分 |
| 新页面 | `Scaffold` + `PageTopBar` + `ContentPane` + `navigationBarsPadding()`，两套主题各看一遍 |

## 12. 自查清单

提交前在仓库根目录执行：

```bash
# 1. 业务代码里不该出现颜色字面量（白名单见 2.1）
grep -rn "Color(0x" app/src/main/kotlin --include=*.kt | grep -v "/theme/"

# 2. 圆角是否落在档位内
grep -rhoE "RoundedCornerShape\([0-9.]+\.dp\)" app/src/main/kotlin --include=*.kt | sort | uniq -c

# 3. 是否混入表外字号
grep -rhoE "fontSize = [0-9.]+\.sp" app/src/main/kotlin --include=*.kt | sort | uniq -c

# 4. 是否绕过共享组件自建对话框
grep -rnE "^\s*Dialog\(" app/src/main/kotlin --include=*.kt
```

第 4 条命中 `DialogCard` 自身属正常；其余命中要么改用 `AppDialog` / `DialogCard`，要么在提交说明里写明
为什么共享容器不适用（如内容完全自定义、需要独立窗口层级）。

人工核对：

- [ ] 浅色、深色各看一遍，层次是否由色阶而非阴影建立
- [ ] 新增文案双语齐全
- [ ] 新增可点区域按 48dp 处理；用到 32dp 紧凑档时已在注释里说明理由
- [ ] 没有新的字号、圆角、动效时长未登记
- [ ] 窄窗与宽窗都看过（行宽上限 720dp）

## 13. 变更流程

1. 先改本文件：新增档位 / 角色时补表格。
2. 再改 `theme/Style.kt` 的令牌（如涉及）。
3. 再改共享组件（默认外观保持不变）。
4. 最后改页面。
5. 验证 `./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug`；
   涉及 UI 与资源再跑 `:app:assembleRelease`。

反向也成立：如果实现中发现规范挡住了合理需求，先讨论并改规范，不要在页面里悄悄破例。
