Android 开发规范

总则与优先级

· 尽量不依赖第三方库,允许下载第三方库阅读其源码等价实现.引入第三方库会因为上游决策带来难以维护的问题,等价实现更符合实际场景。
· 平台/框架 API 一律查官方文档或源码后再写，禁止凭记忆使用已废弃或已移除的接口。
· 执行任务时偏离需求需要明确理由,作出了什么决策,为什么这么做,比原需求是否更具收益且更合理。
· 若我的决策调整或需求发生变更，请据此对本开发文档进行相应修订，使其与项目演进保持一致。
· 复杂度不会消失，只能决定由谁承担，履行同职责内聚，异职责解耦。在此之上应实现本该如此的简单，不止于设计，代码的质量亦是如此。于此之外将概念落于实地，交互逻辑的简单不该抛去应有的氛围。

核心决策

· 语言：Kotlin
· 界面：Jetpack Compose
· 依赖注入：手动注入（必须）
· 导航框架：navigation3

注释规范

· KDoc：仅用于 public/internal API 表面。
· 私有实现：使用 // 双斜杠注释。
· 注释内容：解释代码意图与设计决策，不复述代码行为。
· 同步要求：代码逻辑变更时，相关注释必须同步更新；未随代码更新的注释视为缺陷。
· 禁止内容：溯源、背景等无关信息。
· TODO 格式：// TODO(owner/issue): 说明。

代码组织

· 同职责内聚，异职责解耦。
一个文件可容纳多个紧密相关的逻辑，避免因刻意拆分而导致过度碎片化。
· 组件位置：跨页面复用上提至 ui/component/；无跨页面复用下沉到页面 component/。
· 子目录采用语义命名，父目录采用泛义命名：父目录表示这里可能有什么，子目录则明确是什么。
· 页面根包禁止平铺骨架以外文件。仅允许按需创建子目录收敛页面所需的其它业务。
· 页面骨架白名单：XxxScreen.kt、XxxUiState.kt、XxxViewModel.kt。其余文件必须进入 component/、compact/、medium/、expanded/ 等子目录。
· 组件上提标准：跨 2 个及以上页面复用，或属于统一布局风格的通用组件（对话框、弹出提示、错误横幅、开关按钮等），才可上提至 ui/component/。
· utils/ 必须限定为无状态、纯函数、无 Android 依赖；否则归入对应层。
· data/ 建议按官方指导细分。
· 不引入 domain/ 层。

缓存与磁盘产出

· 任何落盘的产出（缓存、临时文件、异常日志、下载中转文件）都必须在 `data/cache/CacheInventory` 登记分类、归属范围与回收方式；未登记的产出视为失控。
· 归属范围决定回收边界：`cacheDir` 内属系统「清除缓存」作用域，应用可随时整体回收；应用专属目录仅在该项自身策略下回收；公共下载目录属用户可见数据，禁止由「清理缓存」批量删除。
· 缓存必须有界或可回收：LRU 类缓存须显式声明上限，不得沿用依赖库按可用空间推算的默认值；中转文件须能在流程结束、冷启动、超期三个路径中被清理。
· 落点路径只在管理该目录的一方定义（如元数据缓存、下载器各自提供路径入口），统计与回收一律引用该入口，禁止在别处重新拼装同一路径。
· 缓存治理暴露给用户的文案属用户可见内容，须入资源并中英同步；仅日志正文与异常信息可硬编码。
· 用户数据的回收必须由用户显式触发（如删除曲目），不纳入自动清理。

设计决策

· 页面根包禁止平铺骨架以外文件。仅允许按需创建子目录收敛页面所需的其它业务。
· UI 组件原子化，由组装器组装页面 component/ 或 ui/component/ 下的组件，以显示不同布局,不将布局硬编码进同一文件。
· 布局分发：基于 WindowSizeClass 和必要的显示控制分发。

国际化与文案

· 用户可见文案一律入资源文件：默认 values/strings.xml（中文）+ values-en/strings.xml（英文），禁止在 Kotlin、资源 XML、Manifest 中硬编码。
· 新增或修改文案必须中英同步，禁止只改一侧；占位符、格式与标点需两边一致。
· Compose 层统一用 stringResource 取文案；非 Compose 上下文（Service、通知、广播接收器、Application 等）必须按应用内语言构造本地化 Context 后再取资源，不得用系统 Context 取用户可见文案。
· 服务端下发的动态内容（如更新说明）不属硬编码范畴；需多语言时由数据源提供多语言字段，客户端按当前语言选择。
· 例外：不面向用户的字符串（日志正文、异常信息、断言信息）可不入资源。

安全与隐私

· 权限申请必须遵循最小必要原则和自使用处申请(功能触发时申请不能触发后申请避免权限申请弹窗覆盖后续功能弹窗产生竞态).权限状态管理器统一处理。
