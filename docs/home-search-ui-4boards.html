首页 · 在线搜索与搜索历史 UI 改版

4 个设计方向（板 A–D）· 竖屏 360dp / 横屏 800dp 对照 · 供讨论后定一板再实施

已采纳：板 C 单行横滑。 按实施反馈调整为：历史常驻搜索条下方，搜索结果排在历史之后（不做分栏常驻，保留单列上下堆叠）； 面板内标题、搜索条、历史、结果四处统一取 12dp 区块间距。横竖屏共用同一套布局。

共同前提：面板落在封面衍生的深色沉浸背景上，前景一律白色系；历史统一改为 半透明微圆角标签卡（填充 白 12% / 描边 白 18% / 圆角 10dp / 高 32dp）， 差异集中在「标签如何组织」「搜索条怎么处理」「横屏怎么用横向空间」。

板 A

轻量胶囊流

最小改动方向：搜索条加半透明填充、描边柔化；历史由竖向列表改为流式标签，清空沿用标题行尾部图标。

要点

  • 历史由「竖排 10 行」变「2–3 行标签」，省下大量纵向空间给结果区
  • 搜索条加 8% 白填充，与标签同一套半透明语言
  • 横屏限宽居中，避免 800dp 拉条

代价

  • 清空仍是纯图标，含义靠约定
  • 横屏限宽后两侧留白较多，右侧未利用
板 B

历史卡片容器

历史整体收进一张半透明圆角卡片，卡内抬头带时钟图标与「清空」文字按钮；标签填充更淡，以在卡片内仍可辨层次。

要点

  • 「清空」由图标改文字按钮，误触代价高，语义显式
  • 卡片把历史与下方结果区分开，层次更清楚
  • 卡内标签 8% 填充，卡片 6% 填充，两级透明度

代价

  • 多一层容器，历史少时（1–2 条）卡片显得空
  • 比板 A 多约 20dp 纵向占用
板 C

单行横滑

历史压成一行横向滚动标签，行尾渐隐提示可滑；配合更矮的搜索条，把纵向空间几乎全留给结果。

要点

  • 历史常占位固定（约 68dp），历史 0 条到 10 条都不跳动
  • 横屏天然适配：一行能放完全部 10 条，不用渐隐和限宽
  • 搜索条降到 44dp，与单行历史的紧凑节奏一致

代价

  • 竖屏只能看到约 3 条，其余要横滑，可发现性差
  • 横滑手势与 Pager 横向翻页同向，需确认不冲突
板 D

横屏双栏

竖屏同板 A；横屏改左右分栏——左栏固定 340dp 收搜索条与历史，右栏整块留给搜索结果，横向空间真正被用起来。

要点

  • 横屏结果列表与输入区分栏，边搜边看，不用上下找
  • 历史标签在窄栏内自动折行，竖屏/横屏同源同款
  • 结果区变窄后单条曲目信息需要重新排版（横屏可用横向布局）

代价

  • 改动最大：结果列表也要按形态分栏，等于横屏重做一版
  • 右栏在「只看历史」时是空的，需要一块引导态
