## 功能详解

每个功能按「它是什么 → 怎么用」给出。所有操作路径均与当前代码一致。

### 一、播放与界面

- **播放变速** —— 0.5x ~ 2.0x 实时变速,±0.1 步进,由 AudioTrack 原生处理,不做软件重采样。
  - **使用路径**:首页长按「上一曲」或「下一曲」→ 弹出变速对话框 → 点击中间数值即重置为 1.0x。
- **定时关闭** —— 到点后当前曲目播完即停,并结束应用进程。
  - **使用路径**:竖屏标题栏左侧计时按钮 → ±5 分钟(1 ~ 999)→ 确定;计时中标题下方显示剩余分钟数,点击即可取消。
- **首页手势** —— 三页并列:搜索页 / 播放页 / 歌单页,默认落在播放页。
  - **使用路径**:右滑 → 搜索页;左滑 → 歌单页;上下滑动 → 切换上 / 下一曲(可在设置关闭,按住滑动会先显示切歌预览文本,位移回落到起点附近即取消)。
- **自适应布局** —— 基于 WindowSizeClass 在竖屏单列与横屏双栏间切换组装。
  - **使用路径**:竖屏标题栏右侧旋转按钮可强制进入横屏;横屏下点击封面区域进入 3D 封面轮播,拖动切换、点居中封面播放、点侧边封面选中、点空白退出。
- **主题与多语言** —— 跟随系统 / 深色 / 浅色三态,简体中文 / English / 跟随系统热切换。
  - **使用路径**:设置 → 外观 → 主题(切换带圆形揭示动效);设置 → 语言 → 选择语言。

### 二、歌词

- **歌词渲染** 逐字渲染同步跳动或整行高亮。
  - **使用路径**:歌词随播放自动滚动;设置 → 播放 → 「逐字渲染」控制是否逐字高亮跳动;歌词区单击可显隐时间微调按钮(左 `−` 延后 / 右 `+` 提前,每次 100 ms)。
- **歌词拖拽播放与快速滑动切歌** —— 在歌词区上下拖拽可实时调整播放进度。
  - **使用路径**:缓慢拖拽 → 歌词跟手滚动,与某句对齐后标识转为确认色释放即从该句起播,未对齐则弹回原处。快速滑动 → 按上下滑动切歌处理。
- **逐字对齐** —— 把只有逐行时间轴的歌词,用音频本身对齐成逐字时间轴。
  - **使用路径**:长按歌词区 → 「逐字对齐」→ 后台解码对齐,进度显示在竖屏标题区,可离开页面继续进行。
- **歌词自动补译** —— 一键为尚无译文的歌词行补齐中文译文。
  - **使用路径**:长按歌词区 → 「编辑歌词」→ 「自动补译」→ 进度对话框可选「后台继续」;可随时再次发起,把剩下的补齐。
- **歌词编辑与导入** —— 长按歌词区 → 「编辑歌词」→「编辑本行」,或「本地歌词」从文件选择器导入任意文本格式;歌词长按菜单亦可直接搜索当前曲目。
- **歌词排版** —— 音乐面板 / 首页竖屏 / 首页横屏三场景各自独立的字号、显示行数与横屏 3D 强度。
  - **使用路径**:设置 → 排版(字号 12 ~ 24 sp;行数按场景提供 3/5、3/5/7/9/11、7/9/11 预设;横屏 3D 强度 0 ~ 2,步进 0.25)。

### 三、音乐来源

- **本地曲库** —— 基于 MediaStore 扫描设备音频(仅收录 `IS_MUSIC` 且时长 ≥ 30 秒的曲目,按标题排序),并支持从系统分享 / 打开方式导入音频。
  - **使用路径**:首次授权后自动扫描;队列面板头部「刷新」按钮可随时重扫;在文件管理器中选择「用忆潮音乐打开」或分享音频到本应用,即以后台播放方式接管并挂上迷你播放器。
- **代理音源与自定义平台** —— 导入第三方音源,自定义各平台的搜索、播放地址、歌词与封面解析;获得完整能力。
  - **使用路径**:设置 → 代理音源 → 「导入音源」→ 三选一:本地文件、链接导入、文本导入;导入后列表项右侧开关启用 / 停用,垃圾桶图标移除。也可以选择「用忆潮音乐打开」或分享到本应用完成导入。代理音源开发规范详见 [忆潮代理音源规范](docs/忆潮代理音源规范.md)(v1.2.0)
- **每日推荐** —— 基于歌词画像的推荐:以收藏歌曲的歌词画像在词面、概念、节奏三个通道打分,再经 MMR 多样性重排,输出 5 首轮播。
  - **使用路径**:在线搜索页的每日推荐轮播每 4 秒自动切换;右上刷新按钮强制重算;点击卡片播放;卡片右侧「心碎」按钮一键拉黑该曲,不再推荐。
- **黑名单与跳过反馈** —— 拉黑立即生效、持久保存,跳过行为也参与后续推荐。
  - **使用路径**:队列曲目行左滑 → 拉黑;设置 → 黑名单显示已拉黑数量,可一键重置让它们重新参与推荐。

### 四、歌单与队列

- **智能歌单** —— 常听 / 收藏 / 专辑 / 歌手四类由曲库实时派生。
  - **使用路径**:左滑进入歌单页 → 点任一系统歌单卡片进入详情;详情页顶部「播放全部」整单播放;点击首页歌手信息行可直达该歌手的歌单(多位歌手时先弹出选择)。
- **自定义歌单** —— 新建 / 重命名 / 删除 / 批量添加 / 拖拽排序。
  - **使用路径**:歌单页 → 「新建歌单」;详情页「添加歌曲」多选批量加入;长按行内排序手柄拖动即调整顺序(长按拖拽,实时同步到播放队列);歌单行右侧「更多」→ 重命名 / 删除。
- **播放列表** —— 播放列表。
  - **使用路径**:播放页右下角「播放列表」按钮(横屏同位置)打开,在竖屏与横屏控制栏上滑该按钮同样打开,支持「滚动至顶」与「定位当前」悬浮按钮;曲目行左滑拉黑、右滑打开高级菜单(分享 / 设为来电铃声 / 设为闹钟铃声 / 查看频谱)、长按删除。
- **歌单排序** —— 播放列表头部排序按钮,支持默认顺序 / 新旧 / 标题 / 歌手 / 专辑 / 时长,并可正逆序切换。
  - **使用路径**:队列面板头部排序按钮 → 选择规则(仅对默认全量队列开放,自定义歌单保留自己的拖拽顺序)。
- **歌单切换** —— 播放列表头部歌单副标题。
  - **使用路径**:播放列表头部歌单副标题(横屏同位置)打开;显示当前歌单(点击可快捷切换);

### 五、分析与音质

- **曲库分析** —— 一次遍历产出两路结论:音质异常(伪装无损)与疑似 AI 合成音乐;按格式定位全库并可直接跳转。
  - **使用路径**:竖屏长按控制栏「播放列表」按钮 → 曲库分析面板 → 自动开始分析(关闭面板不中断,竖屏标题区显示「曲库分析中 x/y」);面板内含格式占比圆环与「按格式定位」列表,顶部两项为「音质异常」与「疑似AI」;点击任一行即把该分类设为播放队列并跳到播放列表;右上刷新按钮可随时重新分析。
- **频谱分析** —— 解码整首音频并渲染时频频谱图。
  - **使用路径**:播放列表曲目右滑 → 高级菜单 → 「查看频谱」→ 等待解码进度 → 查看频谱图、源文件参数与两路结论 → 长按图表 → 「分享图片」或「保存图片」。
- **USB 音频独占** —— 把播放钉到 USB 解码器,并向原生音频策略申请位完美输出(`setPreferredMixerAttributes` + `setPreferredAudioDevice`):不混音、不调音量、不加音效。混音器属性按当前解码格式挑选,格式变化即重新下发,不会以「已独占」之名静默走回混音路径。
  - **使用路径**:设置 → 播放 → 「USB 音频独占」(悬浮面板的播放设置内同一开关);未接入解码器、或解码器未实现位完美混音时,播放保持系统默认混音输出;解码器插拔即刻生效,无需重启。
- **音频信息** —— 一个面板呈现当前播放链路,按「音频源 / 音频参数 / 播放链路 / 当前输出设备」四组展示;平台读不到的字段直接不产出该行,而不是留空。
  - **展示内容**:源文件路径与体积、格式、解码器、原始 / 输出采样率、比特率、声道布局、重采样、品质;音频输出模式(位完美独占 / 系统混音)、音频会话 ID、浮点输出、音频轨实际写出的输出编码、平均延迟、传输状态;以及当前输出设备的类型、名称、地址、支持采样率、通道数,蓝牙链路上还有链路类型、协商出的蓝牙解码器、蓝牙采样率、每样本位数、声道模式与设备类别。面板随播放实时重算整条链路。
  - **使用路径**:竖屏控制栏上滑「播放 / 暂停」按钮 → 面板自底部滑入(悬浮面板同样支持,在面板上任意处上滑即可);下拉、点关闭按钮或点面板外收起。蓝牙设备的名称与地址需蓝牙权限,面板会在当前输出为蓝牙时就地申请;悬浮面板没有承载系统授权对话框的 Activity,该场景由首页权限对话框覆盖。

### 六、悬浮与系统集成

- **悬浮音乐面板** —— 完整播放器以系统悬浮窗(`TYPE_APPLICATION_OVERLAY`)运行,可覆盖在任何应用之上。
  - **使用路径**:设置 → 播放 → 打开「悬浮播放」并授予悬浮窗权限 → 应用退到后台继续播放时顶部出现迷你播放器 → **点击封面**即展开完整面板。面板内:上滑打开音频信息、右滑进入搜索、左滑打开播放设置,音频信息内下滑收起;点卡片外区域或返回键逐层关闭,在底层按返回键则收起整个面板。
- **迷你播放器** —— 后台播放时贴在屏幕顶部的一条迷你胶囊播放器。
  - **使用路径**:开关同上「悬浮播放」;显示时先呈现 5 个控制按钮(播放模式 / 上一曲 / 播放暂停 / 下一曲 / 播放列表),3 秒无操作自动收起,再显示歌曲名与当前歌词行,歌词行随演唱逐字点亮(关闭「逐字渲染」则整行高亮);左右滑动切换上 / 下一曲,下滑隐藏(回前台自动重置);点击封面展开完整面板,点播放列表按钮弹出迷你列表。应用回到前台时迷你播放器自动隐藏。
- **外部音频接管** —— 从文件管理器或其它应用「打开 / 分享」音频,即以后台播放方式接管。
  - **使用路径**:文件管理器中选择忆潮音乐打开,或系统分享面板分享音频到本应用;应用不弹全屏面板,直接后台播放并挂上迷你播放器。
- **分享与铃声** —— 本地曲目可通过系统分享面板分享,或设为默认来电铃声 / 闹钟铃声。
  - **使用路径**:播放列表曲目右滑 → 高级菜单 → 分享 / 设为来电铃声 / 设为闹钟铃声(需「修改系统设置」权限)。
- **应用内更新** —— 回到前台时每日自动检查一次 GitHub Releases,也可随时手动检查;下载后按 SHA-256 摘要校验再安装。
  - **使用路径**:设置页底部点击版本号 → 手动检查(有新版本弹出带更新日志的对话框,可选「下载」或「稍后」;已是最新 / 检查失败均有提示)→ 下载完成后自动拉起系统安装界面。下载失败可点「在浏览器中打开」,仅允许 HTTPS 下载。
- **存储管理** —— 独立页面盘点各分类占用,按作用域分组。
  - **使用路径**:设置 → 存储管理(进入页面自动重新采样,也可下拉刷新)→ 「清理缓存」一键清理可清理组。
- **崩溃日志** —— 未捕获与捕获异常写入应用专属外部目录,仅保留今日日志,超期自动清理。
  - **使用路径**:设置页底部点击「[日志]」即通过系统分享面板分享今日日志。
- **权限引导** —— 首次启动以卡片式对话框逐项引导授权,其中曲库三项为核心、其余为可选。
  - **使用路径**:对话框列出「全部文件」「音乐访问」「图片访问」三项曲库无法缺失的权限,各带「去授权」;「蓝牙设备」「通知」「后台播放」(电池优化白名单)仅在缺失时追加列出,均不参与对话框的关闭判定,列表整体可滚动,小屏或横屏下不会裁掉末项。三项曲库权限授予后对话框自动关闭,并自动开始扫描曲库;跳转系统设置页后应用会被自动带回前台。

## 架构

应用遵循 **MVVM + 单向数据流**:状态由 `ViewModel` → `UiState` → UI 自上而下流动,事件由 UI 自下而上传递;共享数据逻辑位于 `data/` 层并通过 Repository 暴露,全部由**手动依赖注入**组装——每一个应用级单例挂在 `Application` 上,并通过具名组合局部(CompositionLocal)暴露给界面树。

页面代码采用**分形态组装(per-form assembly)模式**:

- `{Screen}Screen.kt` — 页面入口:在 compact/expanded 形态间分发并处理跨形态副作用,不承载布局
- `{Screen}ViewModel.kt` / `{Screen}UiState.kt` — 页面级状态与事件
- `compact/`、`expanded/` 下的 `{Screen}Assembly` — 按窗口尺寸类与旋转状态选择对应形态的组装器
- `component/` — 页面专用可组合项,按语义子目录分组(如 bar/、dialog/、panel/、playlist/、player/、search/、shell/、swipe/)

被两个及以上功能复用的代码上提至顶层(`data/`、`theme/`、`utils/`、`ui/`),仅单页使用的代码保留在页面模块内。播放逻辑位于 `data/music`(播放 / 下载 / 分析 / 面板 / 推荐),通过窗口级 `MusicPanelStateHolder` 暴露给 UI;悬浮 UI 拆分为 `floatingwindow/`(视图管理,以及迷你播放器自身的可组合项)与 `ui/component/player`(完整音乐面板及其子部件),实际播放由 `service/MusicPlaybackService`(Media3 ExoPlayer + `MediaSessionService`)驱动。

除页面自身状态外,有两类逻辑刻意置于界面树之外,以便跨重组与旋转存活:首页 **面板状态**(`HomePanelState`,持有播放列表显隐、对话框、滑动控制器与曲库分析会话)与共享**播放状态持有者**。其中曲库分析会话常驻首页层,关闭其面板不会中断正在执行的分析。每日推荐的榜单候选池与播放启动镜像同理:候选池由 `App` 在后台预热,最近一次播放状态镜像落盘,使冷启动后的首帧即为完整内容。

频谱分析是独立页面:分析会话按曲目挂在 `SpectrumViewModel` 中,解码跑在 `Dispatchers.Default` 上,离开页面即随作用域取消;解码本体(`SpectrogramDecoder`)与判定入口(`FullSpectrumAnalyzer`)置于 `data/music/analysis`,与曲库分析共用判定缓存与判据。`FullAnalysisLock` 是「以完整分析为准」的落点——曲库分析的分段采样遇到锁定曲目一律跳过,不再改写其结论。

歌词解析同样收在一处:`data/music/api/LyricCodec` 把各平台的歌词原文(普通 LRC、增强 LRC 的行内字标签、QQ 的 QRC、酷狗的 KRC、酷我的 lrcx)统一解析为同一份 `LyricLine` 列表,逐字时间轴一律归一为绝对毫秒,因此各平台的解析结果可直接互换比较,「逐字优先、无字标签则退化为逐行」的选取策略也只需实现一次。取词、解析、缓存写入与自动补译分别落在 `OnlineLyrics`、`LyricCodec`、`MusicMetadataCache` 与 `data/music/panel/MusicPanelLyricsTranslate`,后者的进度对话框与逐字对齐共用同一组件。酷狗 KRC 是唯一自带译文的来源:`[language]` 元信息块(base64 编码的 JSON,取 `type=1` 段)内的译文按歌词行顺序 1:1 对齐,这类曲目无需调用翻译接口即带译文;只有字标签全零的翻译行仍按时间戳并入。

音频信息面板读的是播放链路本身,不与任何播放器布局耦合:`AudioInfoCollector` 从共享播放状态组装出一份 `AudioInfoSnapshot`,Compose 侧则靠一个版本号触发重算——播放器自身回调(播放状态、起播意愿、音频会话 ID)、`AudioDeviceCallback`(设备插拔)与 `ON_RESUME`(刚授予的权限当即体现)各自使其自增。所有字段均可为空,读不到的字段不产出该行,因此同一个面板覆盖扬声器、USB 解码器与蓝牙链路时,UI 侧无需分支。它打印的链路取值——浮点输出、实际写出的 PCM 编码、位完美独占——由按设备音频输出与 USB 独占模块向上回填到共享状态,面板读到的正是播放路径写入的同一份来源,而非从源格式推断。

无损与线性 PCM 容器的标签重写走 `TagSource`,它只暴露区间读取与区间搬运:标签布局由文件头部与尾部窗口定位算出,音频体按原偏移流式复制,因此数百 MB 的高解析单文件在改写标签时不再整文件驻留内存。各类容器布局——ID3v2、M4A/MP4 盒子表、FLAC Vorbis 注释、Ogg 页序列,以及 AIFF、DSDIFF、DSF、APE、WAV 的 IFF/RIFF 式块结构——只需给出「头部字面字节 + 音频体区间 + 尾部字面字节」交给写入方。

## 权限

| 权限 | 用途 |
| --- | --- |
| 悬浮窗 | 悬浮音乐面板与迷你播放器 |
| 全部文件访问 | 导入与管理本地音乐文件 |
| 音乐访问(`READ_MEDIA_AUDIO`) | 读取设备曲库并播放 |
| 图片(`READ_MEDIA_IMAGES`) | 内嵌封面与本地封面候选 |
| 蓝牙(`BLUETOOTH_CONNECT`) | 读取当前蓝牙输出设备的名称、地址与协商出的编解码器(音频信息) |
| 前台服务(`mediaPlayback`、`FOREGROUND_SERVICE_MEDIA_PLAYBACK`) | 后台播放 + 通知栏 / 锁屏控制 |
| 通知(`POST_NOTIFICATIONS`) | 版本更新下载完成通知(Android 13+) |
| 网络(`INTERNET`、`ACCESS_NETWORK_STATE`) | 在线搜索、歌词与封面获取、检查更新 |
| 音频设置(`MODIFY_AUDIO_SETTINGS`) | 播放引擎的音频配置,含 USB 独占申请位完美混音器所需 |
| 唤醒锁(`WAKE_LOCK`) | 熄屏后维持播放引擎运行 |
| 忽略电池优化(`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`) | 避免后台播放被系统回收 |
| 安装应用(`REQUEST_INSTALL_PACKAGES`) | 应用内更新时拉起系统安装器 |
| 修改系统设置(`WRITE_SETTINGS`) | 将曲目设为默认来电铃声 / 闹钟铃声 |

权限由引导对话框逐项申请:三项曲库权限为必需,蓝牙、通知与电池优化白名单为可选且仅在缺失时列出。当前输出为蓝牙设备时,音频信息面板还会就地申请蓝牙权限。

## 快速开始

### 环境要求

- JDK 21
- Android Studio(建议最新稳定版)
- 包含 API 37(`compileSdk`)的 Android SDK

### 构建

```bash
git clone https://github.com/Evilgodxu/YiChao-Music.git
cd YiChao-Music

# 调试包
./gradlew assembleDebug

# 发布包(需先配置签名,见下文)
./gradlew assembleRelease
```

APK 输出为 `app/build/outputs/apk/` 下的 `EchoTideMusic-<版本号>-arm64-v8a.apk`,仅构建 `arm64-v8a` ABI。

### 发布签名

Release 构建从项目根目录的 `local.properties` 读取签名凭据:

```properties
KEYSTORE_PASSWORD=你的签名库密码
KEY_ALIAS=jh
KEY_PASSWORD=你的别名密码
```

签名库文件默认位于项目根目录 `jh.keystore`(如需调整请修改 `app/build.gradle.kts` 中的 `storeFile`)。两个文件均已被 git 忽略,请勿提交。

### 宣传图

README 使用的带壳截图与首屏宣传图由 `tools/make_promo_hero.py` 从 `docs/Screenshot/` 下的真机截图生成:脚本按屏幕短边等比推导边框厚度、机身圆角与侧键位置,输出透明背景的三张带壳截图(`device-*.webp`)与合成后的 `promo-hero.webp`。

```bash
python tools/make_promo_hero.py
```
