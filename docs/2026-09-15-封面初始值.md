# 2026-09-15 封面进出页闪占位符修复

## 根因
`ui/component/SystemThumbnail.kt` 的 `rememberSystemThumbnail` 用
`produceState(initialValue = null)` 驱动取图。页面进出重建时组合节点重新进入
composition，produceState 一律从 null（占位符）起帧，即便内存缓存已命中该略缩图，
也要等 IO 协程跑一圈后才回填成图，故智能歌单专辑/艺术家列表等封面在进出页时先闪占位符。

## 变更
- `SystemThumbnail.kt`：produceState 前用 `remember` 从缓存同步取回命中位图作为
  initialValue；未命中仍走原 IO 解码回填。键带 coverRevision：封面重写已清空缓存，
  避免旧图作为初始值顶出。

## 坑
- 初始值同步读取仅适用于内存缓存路径。

# 2026-09-15 跟进：缓存被详情页顶掉致进出页仍闪

## 根因
首轮加 initialValue 后仍闪：`SystemThumbnailCache` 上限 12MB（约 47 张 256px 位图）。
进出页面时详情页（`PlaylistTrackRow`）为分组内每首歌各解一张，会顶掉刚展示的列表封面；
返回列表时这些行缓存未命中 → 重新解码 → 闪烁。

## 变更
- `SystemThumbnailCache.MAX_BYTES` 12MB → 64MB（约 250 张），容纳可见列表 + 展开详情。
- `EmbeddedCoverCache` 新增同步 `peek`，非索引曲目重建时同样可同步取初始值。
- `SystemThumbnail.kt` 初始值按 `isMediaStoreIndexed` 分别从两个缓存同步取回。

## 坑
- `EmbeddedCoverCache` 原用挂起 `Mutex.withLock` 保护读写；`peek` 为非挂起同步读取，
  不能复用 withLock。Android `LruCache` 自身线程安全，直接 `cache.get` 即可。
