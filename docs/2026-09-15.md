# 2026-09-15

## 修复：索引曲目封面滚动时先占位符后封面

### 根因
所有封面显示统一走 `ui/component/SystemThumbnail.kt` 的 `rememberSystemThumbnail`。
其中索引曲目每次滚入视口都重新执行 `contentResolver.loadThumbnail`（媒体库查询 + 解码），
结果不驻留内存；行滚出再滚入即从头加载，故先占位符后封面。
非索引曲目已有 `EmbeddedCoverCache` 兜住，唯独索引曲目这条路由没有缓存。

### 变更
- 新增 `data/music/metadata/SystemThumbnailCache.kt`：系统略缩图内存 LruCache，
  键为 (audioUri, sizePx)，上限 12MB，只驻留内存不落盘。
- `ui/component/SystemThumbnail.kt`：索引曲目分支先查缓存，未命中才调 `loadThumbnail` 并回填。
- `MusicPlaybackState.bumpCoverRevision()`：封面重写后同时清空 `SystemThumbnailCache`，
  避免同一 URI 命中旧略缩图。

### 坑
- 封面重写后音频 URI 不变而略缩图已变，仅靠 URI 作键会一直命中旧图，
  必须随 coverRevision 整体清空缓存（与 EmbeddedCoverCache 同处理）。

## 修复：冷启动首页先以空态渲染

### 根因
`MusicPlaybackState.restoreSavedState`（读整份歌单 JSON + DataStore + 排序）只在
`HomeScreen` 首帧后的 `LaunchedEffect` 里触发，首帧前 `playlist` 恒为空，
整个首页处于空值状态；悬浮窗初始化还会再触发一次恢复，重复读盘。

### 变更
- `App.onCreate` 用 appScope 预触发 `restoreSavedState`，首帧渲染时歌单与当前曲目已就绪。
- `restoreSavedState` 去重：`restoreMutex + restoreJob(Deferred)`，首个调用方负责恢复，
  其余调用方（HomeScreen 后续定位逻辑、悬浮窗、授权扫描）共享同一任务并等待完成，
  不再各自重复读盘解析。

### 坑
- 预触发后 HomeScreen 的 `LaunchedEffect` 仍会调用恢复：若恢复直接跳过，
  紧随其后的当前曲目定位逻辑会在空歌单上执行而失效。必须改为等待同一在飞任务（await），
  而非简单地用布尔标记跳过。

## 修复：冷启动首页背景渐变恢复持久化取色

### 根因
冷启动修复后首页首帧即展示歌单与当前曲目，但背景渐变来自系统略缩图的异步取色，
略缩图就绪前背景恒为默认深色，重启后先闪默认色再等加载。

### 变更
- `MusicPlaybackState` 新增取色结果持久化（与播放快照同库）：`saveBackgroundGradient`
  在首页背景真实取色成功后写入曲目 URI 与上下半区平均色；`doRestoreSavedState` 恢复为
  `savedGradient`/`savedGradientUri`。
- `SongGradientBackground` 支持 `restoredColors` 兜底：略缩图未就绪时优先用恢复的取色结果，
  取色完成后自然覆盖；新增 `onExtractedColors` 回调仅上报真实取色结果供上层持久化。
  取色与渐变构建拆分：取色返回上下半区原始色，渐变按 `darkenStatusBarArea` 实时构建。
- `HomeShell` 传入与当前曲目同源的恢复色，并把真实取色结果回写持久化。

### 坑
- 恢复色必须与曲目 URI 绑定：运行时切歌后旧曲目的恢复色仍在，若不加来源校验会闪错颜色，
  故 `restoredGradientFor` 仅在与当前曲目同源时返回。
- 持久化只能写真实取色结果：默认色回落分支不得触发写入，否则会覆盖上次的有效取色，
  故 `onExtractedColors` 仅在取色成功时回调。

## 修复：无损升级后不续播 / 重启后点播放不续播

详见 `2026-09-15-无损升级续播失效修复.md`。

### 根因
1. 换源走了 `playTrackAt`，因 URI 变化重建整条时间线（`setMediaItems + prepare`），
   播放器进入重新准备流程，起播被打断，需手动点播放。
   历史可用的 `refreshCurrentPlaybackSource` 用 `replaceMediaItem` 就地换源，不重建队列。
2. 升级后未立即持久化：进度写入走 3 秒节流，窗口内退出会把**已删除的旧 URI**落盘，
   重启后曲目匹配不到（或被执行不可用清理），进度丢失。
   切歌会即时 `persistState()`，故切歌后恢复正常。

### 变更
- `MusicPlayerHelper`：`playTrackFromProgress` → `swapCurrentSourceToUri`，
  用 `replaceMediaItem` 就地换源 + 按原进度 `seekTo`，保持播放意图，并设置续播锚点。
- `MusicPlaybackState` 新增 `resumeAnchorTrackId`，过渡回调仅在锚点归属曲目上消费锚点；
  `softRelease` / `release` 同步复位。
- `playTrackAt` 设锚点时写入 `resumeAnchorTrackId`。
- `upgradeTrackToLossless` 换源后、删旧文件前立即 `persistState()`。
