# 2026-09-15 无损升级保留封面与背景

## 根因
封面已改由系统略缩图驱动（键为 `audioUri`），背景渐变来自该略缩图的取色并按下标曲目 URI 持久化。
`upgradeTrackToLossless` 升级时会下载新无损文件并替换曲目的 `audioUri`：新文件系统略缩图需等媒体扫描
才就绪，`SystemThumbnailCache` 按新 URI 无命中 → 封面回占位符；背景 `restoredGradientFor` 因
`audioUri != savedGradientUri` 不再返回既有取色 → 回落默认色。虽新文件重嵌同一张封面，显示态仍被重置。

## 变更（方案1：升级音质不改变既有状态）
- `SystemThumbnailCache.remap(fromUri, toUri)`：经 `LruCache.snapshot()` 把旧 URI 的全部驻留略缩图
  改指到新 URI，并移除旧键（避免同一 Bitmap 被双键重复计容）。
- `MusicPlaybackState.remapGradientUri(fromUri, toUri)`：把已持久化的背景取色结果改指到新 URI
  （内存态 + DataStore）。
- `upgradeTrackToLossless`：下载新文件后、切换 `audioUri` 前，先 `SystemThumbnailCache.remap` 与
  `playbackState.remapGradientUri`，使显示端与背景在新文件略缩图就绪前仍承接既有封面与背景。

## 坑
- remap 需先移除旧键再写新键：同一 Bitmap 对象若同时挂在两个键下会被 LruCache 双份计容，可能触发逐出。
- 无损升级流程不调用 `bumpCoverRevision`（封面并未变化），故 remap 不会被缓存清空打断。
